# Приложение DSH Federation: принципы, экраны, режимы, раскладные

Дата: 2026-11-23 · Устройства для проверки: HONOR FCP-N49 (Android 17, API 37, раскладной),
Xiaomi 23122PCD1G (Android 16, API 36, обычный).

## 1. Зачем приложение

Телефон — пульт и, если разрешишь, руки. Пульт: видеть узлы, сессии, переписку, отправить промпт,
подтвердить или отклонить действие агента. Руки: по запросу агента снять экран, тапнуть, ввести текст,
открыть приложение, выполнить shell-команду.

Ключевое правило: **агент не получает прав устройства**. Он присылает запрос, приложение проверяет режим и
политику инструмента, и только потом действует. Решение всегда можно отклонить, и оно попадает в журнал.

## 2. Экраны

| Экран | Что показывает | Compact (сложен) | Expanded (раскрыт) |
| --- | --- | --- | --- |
| Узлы | список узлов, статус, версия, режим доступа | полный экран | левая колонка |
| Сессии узла | сессии: заголовок, cwd, статус, время | полный экран (переход) | левая колонка, под узлом |
| Сессия | переписка, инструменты, статус | полный экран (переход) | правая колонка |
| Промпт | поле ввода, вложения, отправка | нижний лист | правая колонка, под перепиской |
| Подтверждение | «агент просит: выполнить `input tap 540 1200`» | диалог | правая колонка, поверх |
| Доступ | режим `sandbox/assist/full`, галочки, журнал | полный экран настроек | правая колонка |

Навигация: одна ось «узел → сессия → переписка». Кнопка «назад» всегда ведёт на шаг вверх, а не
закрывает приложение.

## 3. Режимы доступа и что в них можно

| Режим | Включается | Инструменты | Деградация |
| --- | --- | --- | --- |
| `sandbox` | по умолчанию | свои файлы, сессии, промпты, показ UI | — |
| `assist` | служба доступности в настройках (кнопка «включить») | дерево экрана, скриншот, тап/свайп, ввод, запуск приложений, уведомления | если служба выключена — остаётся `sandbox` |
| `full` | Shizuku запущен по adb (один раз) | всё выше + `input`, `pm`, `am`, `dumpsys`, буфер обмена | без Shizuku — честно `assist`, `capabilities.full=false` |

Политика инструмента: `auto` (можно сразу), `ask` (по умолчанию для опасного), `deny`. Значение по
умолчанию: `phone_shell` и запись вне своей папки — `ask`; чтение своего — `auto`.

## 4. Принципы, которые не обсуждаются

1. **Песочница по умолчанию.** Свежая установка не умеет ничего вне себя.
2. **Каждое опасное действие — с подтверждением и в журнале.** Журнал виден в приложении и на хабе.
3. **Стоп-кран.** Кнопка «стоп» в уведомлении и в приложении гасит команды до следующего подтверждения.
4. **Токен узла — не пароль пользователя.** Отзыв токена на хабе мгновенно закрывает доступ телефону.
5. **Постоянное уведомление службы.** Иначе Android 17 убьёт фоновую работу. Это цена доступа, а не баг.
6. **Никакого скрытого поведения.** Всё, что приложение делает по запросу агента, видно в журнале.

## 5. Раскладные экраны

Устройство проверки — HONOR FCP-N49: два дисплея, внутренний 2156×2344 px при 480 dpi (около 718 dp по
ширине) и внешний 1060×2376 px (около 353 dp). При сгибе меняется не только размер, но и постура.

| Ширина окна | Класс | Раскладка |
| --- | --- | --- |
| < 600 dp | Compact | одна колонка, переходы между экранами, нижняя навигация |
| 600–839 dp | Medium | две колонки: список слева, деталь справа |
| ≥ 840 dp | Expanded | три зоны для планшета и веба |

Как это делается в коде:

- `WindowSizeClass` (Material 3 adaptive) выбирает раскладку по ширине, а не по устройству;
- `androidx.window` + `WindowInfoTracker` дают `FoldingFeature`: `orientation` (вертикальная/горизонтальная
  складка), `state` (`FLAT` / `HALF_OPENED`), `bounds` — по ним контент разносится по половинам и не
  заезжает на петлю;
- `android:resizeableActivity="true"`, состояние в `ViewModel` + `rememberSaveable`: сгиб и разгиб не
  теряют открытую сессию и черновик промпта;
- две панели не «схлопываются» в одну при `HALF_OPENED`: список остаётся слева, деталь справа, как на
  ноутбуке-раскладушке;
- проверка: `adb shell wm size` показывает смену дисплея, а скриншоты обеих раскладок — в артефактах
  приёмки.

## 6. Как проверяется на живом телефоне

1. `adb devices` — устройство видно (USB или Wi-Fi-отладка).
2. Установка APK: `adb install -r app-debug.apk`.
3. Список узлов и сессий: скриншот + `uiautomator dump` (тексты и `content-desc` в дереве, не по OCR).
4. Тап по элементу и проверка результата: `dumpsys window | grep mCurrentFocus` до и после.
5. Сгиб/разгиб: `adb shell wm size` до и после, скриншоты обеих раскладок, состояние экрана сохранено.
6. Режимы: в `sandbox` попытка `phone_ui_tree` возвращает отказ; в `assist` — дерево; без Shizuku `full`
   отдаёт `capabilities.full=false`, а не падает.
7. Опасный инструмент: запрос `phone_shell` появляется в подтверждении, отказ — в журнале.

## 7. Чего приложение не делает

- Не хранит ключи LLM и не ходит к провайдерам — только к хабу.
- Не исполняет промпты само: ходы исполняет узел, где живёт сессия.
- Не работает в Play-политике: автоматизация через службу доступности туда не понесётся, ставим APK.
- Не включает `full` само: только пользователь, только после Shizuku по adb.

## English

The app is a remote control that can also become hands. `sandbox` (default) touches only its own data;
`assist` unlocks screen tree, screenshots, taps, typing and app launching through an accessibility service;
`full` adds shell-level operations (`input`, `pm`, `am`, `dumpsys`, clipboard) via Shizuku started once over
adb. The agent never gets device rights — it asks, the app checks the mode and the per-tool policy, and the
decision lands in the audit log. A stop switch halts commands. Foldables: `WindowSizeClass` picks compact
(under 600 dp), two-pane (600–839 dp) or three-zone (840 dp+) layouts, while `FoldingFeature` keeps content off
the hinge and state survives folding and unfolding. Verified on HONOR FCP-N49 (Android 17, 2156×2344 inner /
1060×2376 outer) and a regular Xiaomi phone (Android 16).
